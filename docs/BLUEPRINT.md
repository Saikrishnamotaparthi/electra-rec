## Data Model

### `applications` Collection

| Field | Type | Description |
|-------|------|-------------|
| `applicationId` | string | `GE26-XXXXX` generated by server |
| `submittedAt` | number | Unix timestamp (ms) |
| `updatedAt` | number | Unix timestamp (ms) |
| `status` | enum | `submitted` \| `reviewed` \| `shortlisted` \| `rejected` |
| `emailStatus` | enum | `pending` \| `sent` \| `failed` |
| `emailError` | string \| null | Last email error message |
| `lastEmailAttemptAt` | number \| null | Timestamp of last email attempt |
| `personal` | object | fullName, registrationNumber, phone, email, academicYear, branch |
| `application` | object | portfolio, role, existingMember, existingTeam |
| `answers` | object | 9 conditional text fields |
| `photo` | object | googleDriveUrl |
| `metadata` | object | userAgent, createdAt, updatedAt, statusChangedAt, statusChangedBy |
| `archived` | boolean | Soft-delete flag |

### `counters` Collection

| Field | Type | Description |
|-------|------|-------------|
| `applicationIds.value` | number | Monotonic counter for application IDs |

## Security Model

### Firestore Rules

- **Create**: Anyone can create an application (public form)
- **Read/Update**: Only authorized admin emails
- **Delete**: Denied (use archive instead)

### Cloud Functions

- `submitApplication`: Public, validates payload, generates ID, sends email
- `resendConfirmationEmail`: Admin or the application owner
- `updateApplicationStatus`: Admin only
- `getRecruitmentStats`: Admin only

### Admin Auth Flow

1. User clicks "Admin Login" → Google sign-in popup
2. Frontend checks `isAuthorizedAdminEmail(email)`
3. If not authorized → `signOut()` + error message
4. If authorized → navigate to `/admin/dashboard`
5. Firestore rules independently enforce the same allowlist

## Conditional Logic

### Member Flow
- Answers: opinion, learningGoals, teamExperience, commitment
- No existingMember question (assumed false)

### Co-Lead + Existing Member
- Answers: opinion, learningGoals, coLeadMotivation
- Asks existingTeam (Marketing / Content / Creative Design only)

### Co-Lead + Non-Member
- Answers: opinion, learningGoals, coLeadMotivation, conflictHandling, initiatives, leadershipExperience, taskPrioritization

## Email System

- Transport: Nodemailer with Gmail SMTP
- Secrets: `GMAIL_USER`, `GMAIL_APP_PASSWORD` (Firebase secrets)
- Templates: Branded HTML with charcoal/gold palette
- Status tracking: `emailStatus` field on each application document

## Excel Export

- All-applications workbook with 6 domain sheets + summary
- Per-portfolio single-sheet exports
- Columns: Application ID, Name, Reg Number, Phone, Email, Year, Branch, Portfolio, Role, Status, Submitted Date, key answers

## Performance Notes

- Admin pages are lazy-loaded via `React.lazy`
- Firestore composite indexes pre-deployed for common query patterns
- Application list uses cursor-based pagination (20 per page)
- Draft autosave uses localStorage (500ms debounce)
- Images are Google Drive links (no proxying/storage costs)
